## test-v2 generation

`scripts/dataset/generate_v2.py` (metadata: `data/generation_meta_v2.json`; per-item rejection
log: `data/audit/generation_v2_log.jsonl`).

- Generator: `google/gemini-2.5-flash` via OpenRouter, temperature 0.9, reasoning effort low,
  the same prompt templates, label filters and argument rules as test-v1
  (`scripts/dataset/generate.py`), **new seed 20260930** (test-v1: 20260929).
- Category quotas identical to test-v1: direto 105, parafrase 87, ambiguo 70, multiturno 35,
  fora_escopo 35, adversarial 17.
- Per-tool stratification: direto/parafrase/multiturno have a per-tool quota (remainders rotate
  over one shuffled tool order), so every tool has 12 or 13 single-label cases; ambiguo is split
  evenly over the 8 confusable groups (9 or 8), fora_escopo over the 5 topics (7 each),
  adversarial over the 4 attack kinds (5/4/4/4).
- Mock-DB consistency: each item's customer and the order ids offered to the generator are drawn
  among orders whose state (`mcp_server/MOCK_DB_NOTES.md` archetype, `compatible_tools`) lets
  the target tool complete (for ambiguo: the group's first tool). Mentioning any other order id
  rejects the item. Order ids always belong to the case customer.
- Labels: `acceptable_skills` derived from `acceptable_tools`; ambiguo label sets come from the
  group spec; fora_escopo is `__abstain__` (optionally `escalate_to_human`); args use only real
  parameter names of an acceptable tool (`mcp_server/tools_list.json`). Adversarial policy
  (`data/README.md`): `tool_by_name` accepts the named tool first, keeping the generator's
  labels as alternatives; a `decoy` item may not accept the named tool; injection and abuse are
  `__abstain__`/`escalate_to_human`.
- Dedupe and leakage, all rejected slots regenerated:
  - exact normalized text, or `SequenceMatcher` ratio >= 0.9, against all 500 existing cases
    (seed + synthetic = dev + test-v1);
  - the same against every router-visible catalog text unit (tool titles, descriptions and
    `_meta` examples in `tools_list.json`, the three `SKILL.md`, the server `instructions.md`,
    the router prompt fragments), compared per user turn;
  - semantic cosine >= 0.9 with the local embedder `qwen3-embedding:8b-q8_0` (Ollama, via the
    project's `EmbeddingsClient`) against the same two reference sets;
  - `SequenceMatcher` > 0.85 within test-v2 (as in test-v1).
- Every case: `source: "synthetic_v2"`, `reviewed: false`.

## Blind label audit (review B2)

`scripts/dataset/audit.py`. Two auditor models from two different families, neither Claude
(router family) nor Google (generator family), both via OpenRouter:

- **A: `openai/gpt-5.6-luna`** (OpenAI)
- **B: `deepseek/deepseek-v4-pro`** (DeepSeek)

Each auditor judges every case independently, in batches of 5 shuffled cases, with structured
JSON output (strict JSON schema). It sees the conversation, the gold `acceptable_tools` and
`args`, the full router-visible tool catalog and the labelling policy. It never sees the case
category, the source, the other auditor, or any router output. Per case it returns:
`gold_acceptable` (Y/N), `wrong_tools`, `missing_alternatives`, `proposed_tools` (best first),
`out_of_scope`, `escalation_acceptable`, `args_correct`, `proposed_args`, `rationale`.

Audited sets: all 349 test-v2 cases, and the B2 subset of test-v1 (182 cases: every
adversarial, fora_escopo and ambiguo case plus 28/23/9 drawn from direto/parafrase/multiturno
with seed 20260930; ids in `data/audit/test_v1_subset_ids.json`). test-v1 audit results are
written only to `data/audit/`; `data/dataset_test.jsonl` is never edited.

### Adjudication rule (pre-declared, fixed before any audit call)

Per case, two independent dimensions:

1. **Tools.** Both auditors accept the gold -> **keep**. Both reject it and propose the same fix
   (the same set of `proposed_tools` and the same first tool) -> **apply the fix**. Any other
   combination (one accepts and one rejects, or both reject with different fixes) -> **flag**.
2. **Args.** Both say `args_correct` -> keep. Both say wrong and propose the same args
   (names equal, values equal after trim and lowercase) -> apply. Otherwise -> flag.

A case is **flagged** if any dimension is flagged, or if an applied fix would be invalid
(unknown tool, or an arg that is not a parameter of an acceptable tool). Flagged cases keep their
original gold until a human decides. Missing alternatives that both auditors propose on an
accepted case are recorded (`label_audit.both_missing_alternatives`) but **not** applied.

On test-v2 the outcome is written into each row's `label_audit` field:
`{decision: keep|fixed|flagged, reasons, auditors, original?, both_missing_alternatives?}`.
`original` holds the pre-audit `expected` whenever the gold changed, so scoring with the
original labels stays possible (`study rescore` is offline). test-v1 outcomes go to
`data/audit/adjudication_test_v1_subset.jsonl` only.

Reported statistics (`data/audit/summary.json`): raw agreement and Cohen's kappa between the
auditors on `gold_acceptable`, `args_correct`, `out_of_scope`, `escalation_acceptable` and the
first proposed tool; for each auditor against the gold: out-of-scope and escalation agreement
(gold: `__abstain__` / `escalate_to_human` in `acceptable_tools`), first-tool kappa, the rate at
which its first tool is in the gold set, and the gold acceptance rate with a Wilson 95% CI.

### Human review of flagged cases

`data/audit/review.html` is a self-contained page (no external assets) listing every flagged
case of both splits with the gold and the two verdicts. Per case choose `keep_gold`, `apply_a`,
`apply_b`, `custom` (tools best first + args JSON) or `drop`, then **Export decisions JSON**.
Decisions file format:

```json
{
  "format": "label-decisions/v1",
  "dataset": "data/dataset_test_v2.jsonl",
  "dataset_sha256": "<sha of the file the page was built from>",
  "exported_at": "2026-10-01T12:00:00Z",
  "decisions": [
    {"split": "test_v2", "id": "v2-ambiguo-004", "decision": "custom",
     "acceptable_tools": ["request_refund", "cancel_order"], "args": {"order_id": "O0031"},
     "note": "optional"},
    {"split": "test_v1_subset", "id": "syn-adversarial-003", "decision": "keep_gold", "note": ""}
  ]
}
```

`acceptable_tools`/`args` are present only for `custom`. Apply with
`uv run python scripts/dataset/audit.py apply-decisions <file>`: test-v2 rows get the decided
gold, `reviewed: true`, `label_audit.human_decision` (and `original` when the gold changed);
`drop` removes the row. test-v1 decisions are ignored by the command (kept for the replication
analysis). **Applying decisions changes the test-v2 sha256: re-freeze it below before the
pre-registration tag.**
